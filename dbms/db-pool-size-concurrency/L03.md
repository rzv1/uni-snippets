# L03: Introducere in ORM 

## 1. Reducerea Codului Boilerplate: ADO.NET vs. Entity Framework Core
Utilizarea unui ORM (Object-Relational Mapper) precum EF Core elimina necesitatea scrierii manuale a interogarilor SQL si a maparii rezultatelor in obiecte C#.

**Cod Boilerplate (ADO.NET):**
```csharp
using (var connection = new SqlConnection(connString)) {
    var command = new SqlCommand("SELECT Id, Name FROM Customers WHERE Id = @id", connection);
    command.Parameters.AddWithValue("@id", 1);
    connection.Open();
    using (var reader = command.ExecuteReader()) {
        if (reader.Read()) {
            var customer = new Customer {
                Id = reader.GetInt32(0),
                Name = reader.GetString(1)
            };
        }
    }
}
```

**Cod Optimizat (EF):**
```csharp
var customer = context.Customers.Find(1);
```
## 3. Implementarea Claselor Entitate cu Adnotari
Pentru a mapa corect structura bazei de date la obiectele C#, s-au utilizat Data Annotations. Acestea sunt atribute aplicate direct asupra claselor si proprietatilor pentru a defini reguli de schema:

```csharp
[Table("Clienti")] // Mapare nume tabel
public class Customer {
    [Key] // Defineste Cheia Primara
    public int Id { get; set; }

    [Required] // Constangere NOT NULL
    [MaxLength(100)] // Limitare dimensiune coloana
    public string Name { get; set; }
}
```

## 4. Analiza ORM: Avantaje, Dezavantaje si Provocari

### Avantaje ale utilizarii ORM
* **Productivitate:** Permite scrierea rapida a functionalitatilor fara a parasi limbajul de programare principal (C#).
* **Mentenabilitate:** Codul este mai usor de inteles pentru noii dezvoltatori si mai simplu de modificat in viitor.
* **Securitate:** Ofera protectie implicita impotriva atacurilor de tip SQL Injection prin tratarea automata a parametrilor.
* **Independenta de furnizor:** Faciliteaza migrarea intre diferite motoare de baze de date (SQL Server, SQLite, PostgreSQL).

### Dezavantaje ale utilizarii ORM
* **Supraincarcare (Overhead):** Generarea automata a interogarilor consuma resurse suplimentare de procesare fata de SQL-ul nativ.
* **Control limitat:** Exista situatii in care optimizarea manuala a unei interogari complexe este imposibila fara a recurge la SQL brut.
* **Consum de memorie:** Mecanismul de urmarire a starilor obiectelor (tracking) poate incarca memoria RAM a aplicatiei.

### Provocari intampinate in timpul migrarii
* **Sincronizarea Schemei:** Cea mai mare provocare a fost corelarea modificarilor din cod cu structura bazei de date, asigurand integritatea datelor la fiecare pas.
* **Gestiunea Relatiilor:** Configurarea corecta a legaturilor intre tabele pentru a asigura incarcarea corecta a datelor relationate.
* **Depanarea interogarilor generate:** Analizarea log-urilor pentru a intelege SQL-ul generat sub capota si pentru a identifica eventualele blocaje de performanta.
